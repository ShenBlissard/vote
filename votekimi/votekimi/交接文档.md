# 班级投票系统 · 项目总结与交接文档

> 文档版本：v1（对应系统 v7）· 编写日期：2026-10-11
> 面向读者：投票发起人（日常使用）、未来维护者（二次开发）

---

## 一、项目概况

**一句话定位**：面向班级场景的单机 H5 投票系统——发起人在网页创建投票，把链接发到微信群，群成员点开链接选自己姓名（凭口令）投票，截止后按发起人预设的规则公布结果。

**建设过程**：历经 1 轮初始开发 + 6 轮用户反馈迭代（v1~v7），每轮均通过自动化冒烟测试（当前 82 项全部通过）后交付。

**当前状态**：
- ✅ 功能完整，本机可稳定运行
- ✅ 所有数据本地存储（`data/vote.db` 单文件，零外部服务、零云依赖）
- ⬜ **尚未部署到公网**——目前仅本机和同一 WiFi 的设备可访问（见"十、公网部署路线"）

**技术底座**：Next.js 16.4（App Router / Turbopack）+ React 19.3 + TypeScript 5 + Node.js 24 内置 SQLite（`node:sqlite`）。除框架本身外无任何运行时依赖，图片识别为本地离线 OCR。

## 二、功能清单（截至 v7）

### 2.1 发起人（创建投票，4 步向导）

| 步骤 | 功能 |
|------|------|
| ① 基本信息 | 主题、说明、截止时间；☐ 允许截止前修改选票 |
| ② 候选人 | 文件导入（Excel/Word/图片OCR/文本）、「排版」按钮、☐ 乱序展示、每人投票人数范围（最少X~最多Y，X=Y为固定人数，1~1即单选） |
| ③ 参与人 | 同样支持导入（Excel 可双列选择：姓名列+口令列）、智能口令识别（四种写法）、一键生成随机口令 |
| ④ 公布设置 | ☑ 匿名投票（**默认开启**）、票数公布（全部/前N名/不公布）、参与情况（四选一）、自动/手动公布 |

创建成功后获得：投票链接（发群）+ 管理链接（仅自己保存）+ 分享文案一键复制 + 口令对照表（如有口令）。

### 2.2 投票人

- 点链接 → 选姓名 →（有口令则输口令）→ 投票（人数范围校验）
- 页面每 **3 秒**自动刷新（发起人公布/撤回、截止/重开，3 秒内自动跟上）
- 截止后显示已公布的结果（按票数排名，并列同名次，含"百分之几参与者投了TA"）
- **投票链接页面不含任何发起人内容**（无返回、无管理入口）

### 2.3 管理页（仅发起人，凭管理链接进入）

- 顶部「← 返回首页」（我发起过的投票）
- 3 秒自动刷新；参与名单分「已投票/未投票」两组（含口令显示）
- **完整结果（仅发起人可见）**：实时票数排名（投票期间也可见）
- 修改截止时间（提前/推迟/推迟到未来=重新开启）、立即截止、公布/撤回公布
- 公布设置随时调整（匿名/前N名/参与情况/自动公布），保存有绿色提示
- 双模式导出：Excel(CSV) 或 复制为微信文字；口令对照表复制

### 2.4 防冒名机制

每位参与人可设独立口令（导入格式"姓名，口令"，留空=无需口令）。设了口令的人必须凭正确口令才能投票/修改。口令对照表由发起人私下分发。

## 三、启动与运维

| 脚本 | 用途 |
|------|------|
| `启动投票系统.bat` | 日常启动：自动安装依赖（首次）→ 构建（首次）→ 就绪后自动开浏览器；崩溃自动重启；已在运行则直接开浏览器 |
| `后台静默运行.bat` | 无黑窗口后台运行（需先用上者完成首次安装构建） |
| `停止投票系统.bat` | 一键停止（创建 `.stop` 标志通知重启循环退出） |
| `重新构建.bat` | 代码改动后重新构建 |

- 访问地址：`http://localhost:3000`；同一 WiFi 手机可访问 `http://电脑IP:3000`（IP 见启动窗口 Network 行）
- **电脑关机/休眠 = 网站下线**，重启脚本即可，数据不丢
- 数据备份：复制 `data` 文件夹；恢复：粘贴覆盖
- 修改代码流程：改 `src/` 下文件 → 运行`重新构建.bat` → 重启

> ⚠️ **维护者注意**：所有 `.bat` 文件为 **GBK 编码 + CRLF 换行**（中文 Windows cmd 的要求）。若用编辑器保存为 UTF-8 或 LF 会导致中文乱码、语法错乱。编辑 bat 后需转回 GBK+CRLF。

```
│   ├── ocr-test.cjs     OCR 单图验证

├── public/
│   ├── vendor/          xlsx / mammoth / tesseract.js 浏览器版（UMD，按需加载）
│   └── ocr/             chi_sim 高精度中文模型（12.5MB + .gz 兜底）
├── data/                vote.db（运行时生成，gitignore）
├── silent.vbs           后台运行辅助
└── *.bat                启动/停止/构建脚本（GBK 编码）
```

**关键机制**：

1. **动态刷新**：投票页与管理页均每 3 秒 `fetch` 轮询（`cache: "no-store"` 强制绕过浏览器缓存）。未用 WebSocket/SSE——班级规模下轮询足够且实现简单可靠。
2. **导入组件按需加载**：xlsx/mammoth/tesseract 三个大库通过 `<script>` 标签在首次导入时才加载（UMD 全局变量），不进主包。
3. **OCR 管线**：图片 → 预处理（宽<500px 自动 3 倍放大；平均亮度<120 自动反色，支持深色截图）→ tesseract.js 最佳中文模型识别 → 逐行进入与手动输入完全相同的分词器。
4. **前后端同一套解析**（`src/lib/shared.ts`）：手动输入、Word、Excel、OCR、API 调用全部经过同一个 `parseVoterEntries`，行为完全一致。

## 五、数据模型（SQLite）

```
polls      投票主表
  id, title, description
  min_choices / max_choices      每人投票人数范围
  shuffle_candidates             候选人乱序展示（0/1）
  anonymous                      匿名投票（默认1：管理页不显示谁投了谁）
  deadline                       截止时间 ISO
  allow_change                   允许截止前修改
  auto_publish                   截止后自动公布
  pub_top_n                      票数公布：-1=全部 / 0=不公布 / N=前N名(按名次)
  turnout_mode                   参与公布：none/voted/not_voted/both
  published / status             公布状态 / open|closed
  admin_token                    管理凭证（32位随机，管理链接的一部分）
  created_at

candidates  候选人（id, poll_id, name, sort_order）
voters      参与人（id, poll_id, name, passcode[明文，见已知限制], 唯一约束 poll+name）
ballots     选票（id, poll_id, voter_id 唯一=一人一票, submitted_at）
choices     选票明细（ballot_id + candidate_id 联合主键）
```

**状态机**：`open` →（到期 或 手动截止）→ `closed`；结果可见 = 已截止 且（`auto_publish=1` 或 `published=1`）；`updateDeadline` 改到未来时间 → 回到 `open`。

## 六、API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/polls` | 创建投票。校验：≥2候选人、人数范围合法、pubTopN∈{-1,0,1..候选数}、截止时间在未来、名单去重 |
| GET | `/api/polls/{id}` | 公共信息：主题/范围/截止/候选人（原始顺序+乱序标记）/名单姓名/状态 |
| GET | `/api/polls/{id}/voter-status?name=&passcode=` | 查询某人是否已投；有口令者须口令正确；choices 仅在"已投且允许修改"时返回 |
| POST | `/api/polls/{id}/vote` | 投票/修改。校验：名单内、口令、开放中、人数范围、候选人有效；事务写入 |
| GET | `/api/polls/{id}/results` | 公共结果：未截止恒为 hidden；公布后按 pub_top_n/turnout_mode 过滤，按票数降序 |
| GET | `/api/admin/{token}` | 管理数据全量：排名、名单（含口令/投票明细，匿名时明细为空）、统计 |
| PATCH | `/api/admin/{token}` | action: `close` / `publish` / `unpublish` / `updateDeadline{deadline}` / `updateSettings{pubTopN, turnoutMode, autoPublish, anonymous}` |

## 七、核心设计决策记录（为什么这样做）

这部分是项目的"隐性知识"，改动前请先理解：

1. **管理链接即凭证**：没有账号系统，`admin_token`（URL 里的 32 位随机串）就是全部权限。首页"我发起过的投票"只存于**创建者那个浏览器**的 localStorage，换浏览器/清缓存即失效——所以创建成功页反复强调保存管理链接。
2. **链接级身份隔离**（v7 最终形态）：投票页是否显示"返回首页"，取决于**导航来源**（从首页列表点入时设置 sessionStorage 标记 `vote_initiator_entry`），而不是设备。因此微信群链接无论谁打开都纯净；发起人经首页进入则有返回。普通投票者即使手动访问首页也看不到任何东西（localStorage 为空）。
3. **匿名默认开启**：管理页默认不显示谁投了谁（roster 的 choiceNames 由服务端清空，导出同步适配）。用户明确要求此默认值。
4. **前 N 名 = 名次语义**：`pub_top_n=N` 表示公布"最终排名 ≤ N 的所有人"（含并列）。名次数值因票数并列失效时，系统在**每次投票后自动向下收缩**到不大于 N 的最大有效名次（宁可少公布），收缩后固定。管理页下拉只列出当前真实存在的名次切分点。
5. **乱序一次性**：开启乱序时，服务器始终返回原始顺序 + 标记，由**客户端在首次加载时随机排序一次并锁定**（orderRef）。曾因服务端每次响应都重新随机导致"勾选时选项乱跳"的 bug，此设计是修复后的定论。
6. **实时票数已整体移除**（v7）：投票期间任何票数对投票者不可见（防跟风）。管理页的"完整结果（仅发起人可见）"保留实时性。历史上曾存在创建选项+管理开关，用户决定全部删除，代码已清理干净。
7. **口令明文存储**：管理页需要展示口令对照表供分发，故不做哈希。这是班级场景下"可用性 > 安全强度"的有意取舍（文档明示）。
8. **分词器规则**（shared.ts `parseVoterEntries`）：一行内任意非常规字符都是分隔符；中文姓名后紧跟 ≥2 位数字=连写口令（1 位数字视为同名后缀如"张三2"）；独立出现的含数字短串=前一人的口令；全角数字自动归一化。此规则由真实用户输入反复驱动形成，改动需全量回归。
9. **紧凑排版**：≤10 人每名一行；>10 人中文逗号连接、口令紧跟姓名（如`张三0421，李四5678`）。导入自动触发，另有手动「排版」按钮。
10. **bat 必须是 GBK+CRLF**：中文 Windows cmd 的硬约束，曾因 UTF-8+LF 导致整段脚本语法错乱，耗费不少排查时间。
11. **OCR 深色截图**：曾因设置 `tessedit_do_invert=0`（禁用引擎自动反转）导致深色截图输出乱码，根因已修复——现在预处理层按平均亮度自行反转，不再依赖引擎猜测；DPI 强制参数也已移除（截图自带 DPI 元数据）。
12. **轮询必须 no-store**：浏览器对无缓存头的 GET 会启发式缓存，曾导致"管理页已截止、投票页迟迟不更新"。所有轮询请求均显式 `cache: "no-store"`。

## 八、已知限制（如实告知）

| 限制 | 说明 | 缓解措施 |
|------|------|---------|
| OCR 生僻字混淆 | "呃→呢、嗡→喻、鹅→忽"类形近字替换无法根治（已实测换模型/锐化/倍率均无效，锐化反而有害已移除） | 正常姓名识别良好；导入结果先进可编辑文本框，人工核对一步不可省 |
| 单机运行 | 电脑关机/休眠即下线；外网/4G 无法访问 | 待公网部署（见第十节） |
| 口令明文 | 数据库可直读口令 | 班级场景接受；如需增强可改哈希+管理页取消展示 |
| 无身份系统 | 管理链接=权限；知道名单+他人口令者理论上可冒投 | 口令私下分发；链接只发班级群 |
| 轮询负载 | 3 秒/次 × 在线人数 | 班级规模（<100人）完全无压力；若数千人需改 WebSocket |
| 首次 OCR 较慢 | 加载引擎约 10-30 秒（仅首次） | 有进度提示与超时兜底（45s/120s），可改用文本导入 |
| 导入文件格式 | .doc 仅支持 .docx（旧版 .doc 不支持）；图片支持 png/jpg/bmp/webp | 让用户另存为 .docx / 截图 |
